第一个关键发现：主目录全是快捷方式

根目录 8076 个文件名形如 000038-ib=7ad7e69e-vs=...-ps=...buf.lnk，都是 Windows 快捷方式（1~1.5 KB），指向 deduped\ 里的真实文件。

而 deduped\ 里的文件名是内容 hash（如 9c2ac78e.buf），不是资源 hash。

逻辑名 → 真实文件 的映射只能从 log.txt 的 Dumping Buffer 行取。

为什么是 4×4 的正交组合

4 个 draw pass（主渲染 / 阴影 / 描边 / 深度）各自需要 4 段 IB。

同一段 IB 在 4 个 pass 里各被一个 draw 使用。

第 3 步：对比 4 套 layout ​

这是决定「用哪套布局」的关键一步。

layoutvb0 分组后vb1 分组后结论
5bfd1268POSITION@0 + NORMAL@12 = stride 24COLOR@0 + TEXCOORD@4 + TEXCOORD1@12 + TEXCOORD2@20 = 28vb0 声明 40 但只用到 24 ✗
bac6075ePOSITION@0 + NORMAL@12 + TANGENT@24 = 40 ✓同 5bfd1268 = 28 ✓✓ 两槽都刚好凑满
7e80b6e1POSITION@0 = 12COLOR + TEXCOORD×3 = 28三槽拆分
8456cccaPOSITION@0 + TANGENT@24 = 40COLOR@0 + TEXCOORD@4 = 12三槽拆分

为什么 5bfd1268 不行

它的 vb0 txt 里声明 stride=40，但按 InputSlot 分组后 slot0 只有 POSITION@0 和 NORMAL@12 —— 到 24 就结束了。

剩下的 16 字节没被任何 element 覆盖。

那 16 字节里确有数据（就是 TANGENT），只是这份 InputLayout 没把 TANGENT 声明进 slot0，而是声明在 @0（和 POSITION 撞车）—— 那是 shader 用其它方式算的切线，不是从 buffer 读的。

选它的后果：vb0 的 stride 40 里后 16 字节读不到语义 → 模型缺失切线 → 光照错乱。

选 bac6075e —— 它是唯一一套 vb0 单独就能凑满 40 字节的（12 + 12 + 16 = 40）。

这一步推翻了两个错误结论

错误一：up 轴是 X

我之前用「沿轴切片的横截面宽厚比」判出 up = X（比值 1.11，其它两轴 2.35 / 2.08）。

那是因为用了已蒙皮的缓冲 —— 腿伸向 X 方向，把 X 拉成了最长轴，切片自然看起来「横截面圆」。

T-pose 下 Y 才是身高方向（尺寸 1.617 在 Y 轴），用标准变换 (x,y,z) → (x,-z,y) 即可。

错误二：数据类型是 CPU-PreSkinning

从 trianglelist 视角看不到 BLEND 语义，我判定这是 CPU 预蒙皮。错。

看不到骨骼绑定数据 ≠ 没有骨骼绑定 —— 那份是游戏在 GPU 上蒙完皮之后的结果，权重早就用掉了。

真正的数据类型是 GPU-PreSkinning： GPU_P12_N12_TA16_C4_T8_T1-8_T2-8_BW16_BI16_

这也解释了 SSMT4 为什么要混标 ​

Category从哪份缓冲取ExtractTechnique
PositionT-pose vb0（stride 40）pointlist
BlendT-pose vb1（stride 32）pointlist
Texcoord已蒙皮 vb1（stride 28）trianglelist

要 T-pose 的形状 + 骨骼权重，同时还要原始 UV。

UV 只在已蒙皮的 vb1 里（T-pose 的 vb1 是纯权重缓冲，28 vs 32 字节）。

这个案例的教训 ​

1. 先看 topology 分布 ​

有 pointlist → GPU 预蒙皮 → 坐标和权重去 pointlist 的缓冲拿。

这一步做错，后面全错（我在这上面浪费了一整轮，模型带踢腿姿势）。

2. 布局要按 InputSlot 分组后看 ​

同一个 vbN txt 里抄着完整的 InputLayout（所有 slot 的元素都在），还有重复 offset 和撞车 offset。

直接按行读会得到错误的 stride。

3. up 轴不要用「最长轴」判 ​

用「沿该轴切片的横截面宽厚比 ≈ 1」，而且必须用 T-pose 的缓冲。

4. striding 和 count 都别信 txt ​

stride 用 vertex-data 反查，count 用 len(buf) // stride。

5. 顶点色的坑有两层 ​

第一层是类型不匹配（劈裂），第二层是校验会骗你。

6. 回读校验的基准要用原始字节 ​

任何「我写进去又读出来一样」的校验，如果写读是对称的，永远通过。
