这套教程讲什么 ​

先明确边界：这套教程不假设你装了 SSMT4，也不假设你装了任何 Mod 工具。

只用：

  • 一个 3DMigoto 的 FrameAnalysis 转储目录
  • Python + numpy
  • 一个文本编辑器
  • Blender

目标是把转储里「某个 IB」对应的模型，还原成一个能编辑的网格，并且这个网格改完之后还能写回游戏。

为什么不用工具 ​

用 SSMT4 这类工具当然更快 —— 点几下就出结果。但你会卡在三个地方：

  1. 工具不支持你的游戏。SSMT4 每个游戏都要写一份 extractor，新游戏出来之前没有。
  2. 工具报错你不知道为什么。看着「无法识别数据类型」的提示，只能去问作者。
  3. 数据类型选错了不会自救。工具给了你几个候选，你不清楚差别在哪，选完发现模型缺了半身。

读完这套教程，这三件事你都能自己处理。

教程怎么组织的 ​

五个步骤，每步都能独立验证：

步骤输入输出怎么验证对了
锁定目标 IB转储目录一个 8 位哈希 + 它的 draw 列表索引数量、贴图反查
搞懂数据类型VB 的 .txt header每顶点 stride 的字段拆分表.txt 末尾的 vertex-data 预览值
切顶点与索引.buf + 字段表顶点数组 + 三角形数组跨缓冲顶点数一致、索引不越界
坐标与朝向顶点数组轴对、绕序对、UV 对的网格法线点积、人形轮廓、贴图采样
做回 Mod改完的网格能写回的原字节重建整条缓冲逐字节比对

每一步都给出明确的通过标准。达不到就不要往下走 —— 后面只会更乱。

一个贯穿全文的例子 ​

教程用一个真实案例展开：IB 7ad7e69e，一个 24068 顶点、29606 三角形的角色模型，带 141 根骨骼。

选它是因为它把坑都踩全了：

  • 同一个模型在转储里有两份顶点缓冲：一份 T-pose（绑定姿势），一份已蒙皮（当前动画姿势）。取错了模型就会摆着一个踢腿姿势。
  • 4 段 IB 被 16 个 draw 引用，分成 4 套不同的输入布局。
  • 顶点色 B 通道 100% 恒等于 128，看着像垃圾数据，其实是着色参数。
  • UV 的 V 轴要不要翻转，靠算法判不出来，得看贴图。

用词约定 ​

  • 「转储」= FrameAnalysis 目录，就是按 F8 生成的那一堆 .buf / .txt / .lnk
  • 「IB」= Index Buffer，8 位十六进制哈希指代它，例如 7ad7e69e
  • 「draw」= drawcall，6 位十进制序号指代它，例如 000081
  • 「数据类型」= GameType，一套字段拆分方案的名字，例如 CPU_P12_N12_TA16_C4_T8_

完整定义见术语表。

前置知识 ​

需要的：

  • Python 基础语法（会写 for 循环和函数就行）
  • numpy 的 frombuffer / dtype 概念（教程里会讲，但见过会更快）
  • 一个 3D 软件的基本操作（导模型、看 UV、看顶点组）

不需要的：

  • dx11 编程经验（教程会解释用到的每一个 API）
  • 图形学数学（叉积、点积这一级别，用到时会说清）
  • 汇编 / 逆向经验
